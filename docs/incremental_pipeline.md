# ATLAS 数据清洗与良率汇总（v1.9.0）

## 目录与入口

所有真实数据、缓存、清理结果、报表和日志必须在 Git 仓库之外。例如：

```text
D:/FT_DATA/
├── LDO/
│   └── WL111/
│       ├── LOT001/
│       │   ├── WL111_LOT001_1#_CP.csv
│       │   ├── WL111_LOT001_1#_RT1.csv
│       │   # CSV准备完成后，输入CSV直接位于Lot根目录，原名保留
│       │   └── summary_cleaning_data/
│       │       └── WL111_LOT001_W01_summary_cleaning.csv
│       ├── LOT002/
│       ├── WL111_BIN良率.xlsx
│       ├── WL111_测试项失效率.xlsx
│       ├── WL111_测试项平均值.xlsx
│       └── .atlas/
│           ├── state.sqlite
│           ├── ingest_backups/    # 已移出Lot的原包、非CSV及嵌套原文件，可恢复
│           ├── input_history/     # 输入改名/修正前的登记信息与旧清洗CSV
│           └── logs/
├── DCDC/
├── Load_switch/
└── _atlas_runs/
```

运行 `python main.py`，选择 **数据清洗与良率汇总** 标签页：

1. 选择 LDO/DCDC/Load_switch 的父目录。
2. 在①CSV准备组点击“预览压缩文件 / 待整理文件”。核对嵌套压缩包完整路径及文件操作清单，此时只读、不解压。
3. 点击“确认解压并整理 CSV”，再次确认后执行。CSV平铺到Lot根目录，原包和其他格式移出Lot备份。
4. 在②清洗与汇总组点击“扫描 CSV / 确认身份”，核对产品、Lot、Wafer、输入文件数和处理动作。
5. 关闭 Excel 中打开的产品报表，点击“执行”。只有已经平铺的直接CSV时，可跳过①。

入口是人工选择目录并执行，暂不后台监控、不联网拉取数据，不改原始文件名。
无需先执行文件名规范化：产品身份以产品目录及对应配置为准，Lot/Wafer 从原名规则识别，
并校验 Lot 目录。厂商文件里的产品前缀可以不同；无法识别或身份冲突仍提示人工确认，
不猜测身份。解压操作不按命名规则筛选；原始压缩包移出Lot备份，不永久删除。
初次运行不会导入旧 Excel 作为历史；会计算当前目录中的所有可识别 Wafer 建立缓存。

## Product Profile

产品文件夹名称必须对应 `config/products.yaml` 中启用的 Product。
只有一个顶层 `products:`；新增产品时在其下面新增条目，不要再写第二个 `products:`。
使用单引号保存 Regex，examples 中 wafer 使用引号保留前导零。

下面是匿名化的完整配置样例（在现有 products 下面添加 WL111）：

```yaml
products:
  WL111:
    enabled: true
    naming:
      version: 1
      regex: '^WL111_(?P<lot>[^_]+)_(?P<wafer>\d+)#_(?P<stage>CP|RT\d+).*\.csv$'
      examples:
        - input: 'WL111_LOT001_1#_CP.csv'
          lot: 'LOT001'
          wafer: '1'
        - input: 'WL111_LOT001_1#_RT1.csv'
          lot: 'LOT001'
          wafer: '1'
    validation:
      lot_required: true
      wafer_required: true
      wafer_min: 1
      wafer_max: 25
    cleaning:
      mode: coord
    columns:
      header: SITE_NUM
      pass_fail: PASSFG
      x: X_COORD
      y: Y_COORD
      soft_bin: SOFT_BIN
    yield:
      good_bins: [1]
      denominator: TotalCount  # 历史字段，失效率固定使用晶圆总die数量
    wafer:
      expected_die_count: 10000
      die_count_tolerance: 50
    automation:
      enabled: true
      test_stage: CP  # 历史兼容字段，不代表实际测试阶段
```

根目录的 LDO/DCDC/Load_switch 只是分类，不决定清理算法。产品级设置覆盖
`pipeline_defaults`；未设置时采用坐标清理、BIN1=Good。
不从文件名推断 CP/FT，不显示测试阶段。`test_stage` 和 `denominator` 保留以兼容旧配置，
无需修改；它们不决定新的测试项失效率口径。命名 Regex 仍须匹配实际文件名。
不同设计改版应使用新的产品记录/目录，避免混合统计。

“数量状态”中的“未配置期望值”表示没有设置预计每片的有效die数量，不是良率失败。
在已有产品配置下添加/修改 `wafer.expected_die_count` 和 `wafer.die_count_tolerance`，
例如预期10000颗、允许偏差50颗；按实际产品数量填写，不要盲用示例值。
产品级设置覆盖 `pipeline_defaults.wafer`；目前全局期望值为 `null`，容差为500颗。
`die差值 = 有效die数量 - 期望die数量`，绝对差值不超过容差显示“容差内”，超过仅警告，
不排除该片，也不改变BIN良率或测试项失效率的实际数据分母。

三个报表及辅助Sheet统一水平/垂直居中，按全部行的显示值和字体估算紧凑列宽，
效果接近Excel自动调整列宽；超出Excel最大列宽的长文本自动换行。
现有报表不会因格式代码变化而自动触发重算。应用新格式时，在运行方式中选择
“仅从缓存重建报表”，扫描后执行即可，不需要强制重算Wafer。重建前关闭Excel报表。

现有 WS0712 Profile 保留了源文件产品名与配置产品名不同的情况：以 WS0712
作为产品文件夹，Naming Regex 负责识别其源文件。Lot 文件夹名称必须与文件解析的 Lot 一致。
已经使用产品配置名规范命名的 `Product_Lot_Wafer#_...csv` 可以直接识别；其他格式使用 Naming Regex。
自动入口读取每个 Lot 目录的直接 CSV；嵌套原始CSV需先执行①整理，旧导入记录需先迁移。
跳过直接目录里已生成的 summary/onlydata 文件。
存在无法识别/身份冲突文件时，阻断该 Lot，其他合法 Lot/产品可继续。

## 压缩包准备与人工确认

- Lot下面可以嵌套多个实际文件夹，递归查找其中的ZIP或单文件GZ；目录层级深度不影响发现。
  ZIP内部子目录中的CSV和 `.csv.gz` 也提取；不支持ZIP内再套ZIP/tar.gz等容器。
  单文件GZ支持 `.csv.gz`；`.std.gz` 为非CSV，不提取。未知GZ类型提示人工处理。
- 第一步是只读预览，显示完整相对路径、CSV成员数和待整理动作，不产生缓存、日志、解压结果。
  预览会读取输入文件内容计算指纹；执行时重新校验。文件内容、时间或集合变化必须重新预览。
  第二步明确确认解压及整理；预览不是执行授权，不会自动删除或搬移文件。
- 全部CSV均提取，不按YAML规则筛选，CSV按原文件名直接放在Lot根目录。已有嵌套CSV也平铺。
  STD/TXT/XLSX等压缩包成员不提取；Lot原有的非CSV（包括ZIP/GZ）和嵌套原文件移出Lot，
  保存到产品 `.atlas/ingest_backups/<运行编号>/<原相对路径>`，可恢复，不永久删除。
  空的输入子文件夹随后移除；Lot本身以及 `summary_cleaning_data` 等已生成结果目录保留，
  产品层级的Excel报表不动。备份范围只限当前Lot输入区域，不清理外部目录。
- 已登记的旧 `imported_csv` 只迁移当前有效成员；历史版本移入备份，不混入新统计。
  同名同内容CSV只留一份；同名不同内容拒绝覆盖并阻止该Lot整理。
  未登记/人工修改的根目录CSV不覆盖；同一已登记压缩包更新成员时，原CSV先备份。
  未变化的CSV保留原路径和时间，所以整包更新只重算内容变化的Wafer。
- 当前包若少于其已登记CSV成员，会拒绝替换，防止残缺输入。原包正常移出Lot后，
  后续清理/绘图只需校验平铺CSV，不要求原包仍存在。新到或变化的包仍阻断该Lot，
  必须先重新预览与整理。删除或修改已登记CSV会提示异常，不能静默漏算。
- 不支持密码保护CSV、tar.gz、嵌套压缩容器；坏包、链接/junction、越界路径、超安全上限
  均拒绝处理。每包最多10000条目、提取CSV共1 GiB。完整解压和同名校验通过后才发布CSV。
  发布失败尽量回滚本次写入，原文件不动；搬移失败时已移文件仍在备份区，未移文件保留，
  详细以日志为准。错误Lot不妨碍其他Lot继续整理。
- 后续身份校验失败的CSV显示 `PENDING_CSV`。可修正规则后重新扫描，或选择CSV行
  点击“忽略 / 恢复所选CSV”。忽略必须用户确认、不删除文件，确认绑定内容指纹；
  内容变化需重新确认，未变化成员迁移时继承确认。身份冲突/Lot不一致/Wafer超范围必须修正。
  CSV准备不计算良率；整理后仍需扫描身份并点击执行清洗与汇总。
- 如需恢复，先关闭处理程序，从对应运行备份中把所需文件复制回原Lot相对位置，再重新预览。
  不要未经确认直接将整个历史导入备份恢复参与统计，也不要删除 `.atlas/state.sqlite`。

## 清理与格式约定

- `coord`：保留按测试顺序最后出现的同坐标记录，坐标必须有效。
- `rt`：沿用原手动算法；有 RT 时保留初测 Pass 和全部 RT 记录，没有 RT 时全留。
  这不是“每颗 die 最终结果”的新算法；重复坐标会单独提示。
- RT 通过明确的 `RT/RT1/RT2` 后缀标记识别，不采用产品名内任意 RT 子串。
- 多文件优先按 Ending Time 排序；缺时间时按初测/明确 RT 序号排序。
  同轮次坐标重叠且先后不明时拒绝猜测，需要补充正确时间/轮次信息。
- 当前 CSV 必须包含表头、随后四行单位/LSL/USL/其他信息和测试记录。
  末尾无名列仅在元信息和全部数据都为空时忽略；含实际内容的无名列提示列号/行号并
  要求人工确认。中间无名列和重复列名仍拒绝，不修改原始 CSV。
  支持 UTF-8/GBK，要求必需列、唯一列名、明确 Pass/Fail 值，同 Wafer 的列和元信息一致。
- 只写整合清理 CSV，保留五行表头结构、source_file 和 ending_time 溯源列。
  文件统一为 `Product_Lot_W01_summary_cleaning.csv`，Wafer 以数字规范化并至少两位补零；
  分段/RT 输入集合只生成一个清理结果，不继承原名里的产品前缀或 CP/FT 字样。
  不生成未清理 merge 或 onlydata；不会删除已有历史产物。

## 增量判断与恢复

业务唯一标识为产品目录中的 `(Lot, Wafer)`。`01` 与 `1` 是同一 Wafer。
旧缓存中唯一匹配的内部键继续复用，新片使用中性内部标识，不猜测实际测试阶段。
若同一产品/Lot/Wafer 存在多套历史标识，要求人工分开目录，不自动合并。
真正不同的 CP/FT 数据不能放在同一产品/Lot/Wafer 输入集合，应使用独立数据根目录。
RT/分段文件属于同一 Wafer 输入集合，不会新增一行“RT Wafer”。

输入集合新增/变化、清理或统计配置改变、cleaned 文件消失/变化时，只重算相关 Wafer。
demo 阶段旧命名不永久保留：输出命名不一致时 Preview 显示 `OUTPUT_NAME_CHANGED`，
执行增量处理会重算这些片并登记规范输出。新结果登记成功后，将未修改的已登记旧输出
移到产品 `.atlas/retired_cleaned/运行编号/原相对路径`，可从那里恢复；不删除原始文件。
旧输出有人工修改时保留并记 WARNING；新目标存在但未登记时拒绝覆盖、要求人工确认。
只重建报表不会更新输出命名；请运行“增量处理”。统一后无变化的片仍正常跳过。
原文件内容不变但修改时间变化，只更新指纹，不重新计算。
若准备CSV来源登记的文件时间变化，需要同时更新来源映射，可能显示 `INPUT_PROVENANCE_CHANGED` 并重算受影响片。
默认利用文件大小和修改时间复用 SHA256，避免重复读取历史大文件。
若担心同大小、同时间的内容被替换，选择“完整校验文件内容”或 `--verify-hashes`。
所有复制操作应先完成再运行；源文件处理期间发生变化会拒绝提交结果。

`.atlas/state.sqlite` 保存状态、输入映射和小型指标，不保存原始 die 明细。
每片成功结果独立提交。失败时保留旧指标，但标记 failed 并排除主表，日志/处理状态 Sheet 明示。
发现输入消失时标记 missing，不删除原始/历史清理文件，也不静默保留旧指标作为有效结果。
若同一 Wafer 仅部分已登记文件消失，也会阻断重算，防止仅用剩余 RT/分段文件产生残缺结果；
请恢复文件后重试；若是有意替换，使用下面的人工确认流程。强制重算不会绕过此完整性检查。
产品级 OS 锁阻止两个任务同时写同一产品；进程退出后锁自动释放。

### 文件改名与有意替换

同名、同路径CSV内容更新，仍按增量判断处理该片；不要求删除缓存。
普通模式可能漏检人为保留相同大小和时间的替换，正式运行建议开启完整校验。

旧路径消失时，自动迁移只接受同一产品/Lot/Wafer 的完整等价输入集合：
文件数一致、保留路径内容不变、消失与新增文件按SHA256和初测/RT序号唯一一一对应。
不会跨片按相同die数量匹配；相同内容的多个候选或改变RT身份都要人工确认。
只读扫描显示 `INPUT_RENAMED`；正常执行才迁移登记并重算该片，更新清洗CSV内的来源路径。
扫描不会改文件名、写缓存或创建历史备份。

无法证明只是改名、内容和名字同时变化，或者工程师有意减少RT/分段文件时：

1. 文件复制完成后，点击“扫描 CSV / 确认身份”。
2. 在身份/良率预览表中用 Ctrl/Shift 选中需要替换的已登记Wafer行。
   可选 `INVALID` 的缺输入片，也可选 `SKIP` 的片以主动完整校验；不能选待识别CSV或新片。
3. 点击“预览 / 确认替换所选片输入”。后台完整计算所选片所有当前CSV的内容指纹，
   展示历史/当前路径、初测或RT轮次、字节数、SHA256和退出/新增/变化标识。
   此时只读；取消或拒绝确认不写缓存、不生成备份、不更新报表。
4. 填写替换原因，并勾选已确认每片的完整初测/RT/分段输入集合。
   文件数量和die数量都是辅助检查，不能证明测量数据完整；由工程师确认。
5. 点击“确认替换并仅重算这些片”，在第二次确认后执行。运行方式自动回到增量模式，
   只处理所选片，按原稳定片标识替换报表对应行，不新增重复行。

确认绑定文件路径/大小/时间/SHA256、配置、该片历史登记和相关压缩包来源。
确认后再改内容、加减文件、重新处理该片或改变配置，会拒绝过期确认并要求重新预览。
发布前还会检查当前输入集合，新增RT不会被静默漏掉。复用旧确认不会再发布另一版。
身份不匹配、未准备/变化的压缩包、无当前CSV、CSV格式和清理校验仍不能绕过。
若整片输入都丢失，先恢复至少一份正确且可识别的CSV，再确认完整集合；不允许确认空集合。

执行后会重新扫描，展示其他片的 `NEW`/`INPUT_CHANGED` 等待处理状态。
这些片不会因本次人工确认被顺带重算；有其他待处理数据时，仍须正常执行增量处理，
才能让产品汇总覆盖全部最新数据。过期确认在重算前被拒绝时，不改原登记或报表。

每次输入改名、修正或人工确认，会在覆盖已登记的清洗结果前备份该片旧版本：

```text
产品/.atlas/input_history/<运行编号>/<Lot>/Wxx_<片标识>/
├── previous_cleaned.csv   # 旧清洗结果存在且内容校验通过时保存
└── record.json            # 旧指标/配置指纹/来源登记，操作类型、原因和确认信息
```

SQLite的 `input_revisions` 和运行日志记录成功发布的修正事件及备份路径。
失败尝试也可能留有旧版本备份，是否发布成功以SQLite事件/日志为准。
只备份受影响片，初次处理、普通无变化重跑不会备份整个Lot/产品；暂不自动清理历史，
存储占用随真实修正次数增加。此处保存旧清洗结果和登记信息，不保存已经被工程师覆盖/删除的原始CSV。
原始数据恢复需依赖工程师另存的文件或原包备份，不要删除 `.atlas` 来解决替换问题。
手工编辑过的旧清洗结果会阻止覆盖，应先另存并确认；不要将历史清洗CSV放回原始输入根目录。

数据清理/校验失败时保留旧清洗文件，旧指标标为失败并退出当前有效汇总。
数据库/审计事务发布失败时尝试恢复原清洗文件，失败的新输出保留为 `failed_new_cleaned.csv` 供排查。
三个Excel导出失败仍按现有机制恢复旧报表，缓存保留待重建状态。

压缩包提取的CSV也适用：同内容改名更新成员路径并保留原包内成员身份；手工修正或有意移除的
原成员转入来源清单的 `retired_members`。原包SHA256及原包备份不变，不伪造修正CSV的原包来源。
未登记/未知身份的包成员变化仍阻断相应Lot，必须先解决身份或重新准备CSV。

三个 Excel 是缓存的展示结果，按稳定 Wafer 标识新增/替换，不直接向 Excel 末尾盲目追加。
报表丢失或上次导出失败可从缓存重建。历史 Wafer 不重算；有变化时重新写三个 Excel。
所有三个报表先写临时文件，再替换；失败时尝试恢复旧报表，保持缓存导出状态待重试。
不要手工编辑自动报表作为新的数据来源，否则后续更新会覆盖编辑。

## 报表与数量校验

每个产品三个 Excel 主表每片 Wafer 一行：

- BIN良率：总良率（默认 BIN1）、各 BIN 占比。
- 测试项失效率：失效die数量 / 晶圆总die数量；低于 LSL 或高于 USL 为失效，
  等于边界通过，单边规格只比较存在的一侧，无规格为 No_SPEC。
  缺测/非有限数值不计失效，但仍在晶圆总die分母中，并在“测试项缺测die数”单独显示。
  有有效坐标时按同坐标最后一条保留记录计算；无坐标只能按记录计数并提示无法识别重复die。
- 测试项平均值：有限有效数字的均值，文本/无有效数字为 NA。

都包含有效die数量、晶圆总die数量、保留记录数、BIN有效记录数、期望die数量、差值、数量状态、规格版本等。
有效die优先为唯一有效坐标数；无坐标时采用有效BIN记录数并标注方法，不能证明重复die是否存在。
期望值未设置时仍显示实际数量，但不会猜测“应该有多少颗”。偏差在配置容差内属正常提示，
超出容差只是警告，不自动拒绝数据或推断漏测。BIN分母保留原来的清理后总记录数口径。
RT 模式若保留重复坐标，记录数与有效die数量可能不同，请根据实际业务规则检查。

测试项两类报表另有“测试项有效数”（有效测试记录数）“测试项规格”Sheet；失效率报表另有
“测试项失效die数”和“测试项缺测die数”。新增测试项自动并入列集合，
不同规格保留版本并提示查规格表，不用首片规格静默覆盖其他规格。
每个报表还有“处理状态”和“数据说明”。日志位于根目录 `_atlas_runs` 与产品 `.atlas/logs`，
记录输入文件映射/指纹、成功、跳过、失败、不可用结果、数量警告和报表更新状态。

升级后正常执行一次增量处理即可生成新失效率报表；原“测试项良率”文件不再更新，
保留为历史文件，可自行归档。通常复用旧缓存；若旧 RT 指标含重复坐标而缺少按die统计，
会提示 METRICS_UPGRADE 并只重算这些片。此情况不能只用 `--rebuild-reports`。
BIN 良率、测试项平均值及原手动统计入口的算法不在本次修改范围内。

## CLI

```powershell
python run_pipeline.py 'D:/FT_DATA' --preview
python run_pipeline.py 'D:/FT_DATA' --preview-archives
python run_pipeline.py 'D:/FT_DATA' --prepare-csv --confirm-archive-cleanup
python run_pipeline.py 'D:/FT_DATA'

python run_pipeline.py 'D:/FT_DATA' --rebuild-reports

```

`--config` 可指定仓库之外的私有产品配置。`--preview` 不创建缓存/输出/日志。
`--rebuild-reports` 只投影已有缓存，不重新检查原始输入是否新增/消失；要更新输入状态请使用增量运行。
失败或存在不可用 Wafer 返回非零退出码，便于未来调度，但本版本不创建定时任务。
